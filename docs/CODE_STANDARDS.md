# Code standards

## General

1. Keep it simple, do not overcomplicate.
2. Comments only when necessary.
3. Be concise: a short README and no emojis.
4. IMPORTANT: avoid overly defensive code. Handle exceptions only when necessary.
5. Use uv: ALWAYS `uv run`, NEVER `python3`.
6. TypeScript: strict mode, never `any`.

## Structure

7. One way to do each thing. The agent reaches the backend only through `agent/api.py`, and the improver only through `agent/improver_api.py`, both on the one client in `agent/connection.py`, the one place with the backend's address. The payroll agent's tools and its check tools' reads take one route, chosen by `agent/tool_route.py` when a run's payroll agents are built, and the Copilot's context layer tools the same route, chosen as a turn is built: `agent/gateway.py`, the AgentCore Gateway's MCP tools signed with SigV4, when `PAYROLLCHECK_GATEWAY_URL` is set, or else `agent/direct.py`, straight to the app through `agent/api.py` and to the context layer over MCP. Each route is one module, both are what `agent/routes.py` says a route is, and MCP tools are called only through `agent/mcp_tools.py`. `PAYROLLCHECK_GATEWAY_URL`, the Gateway's `___` and `bedrock-agentcore` are written in `gateway.py` alone, `PAYROLLCHECK_CONTEXT` and the context layer's address on the laptop in `direct.py` alone, and the targets' names in `routes.py` alone. The payroll agent keeps no memory. The Copilot reaches its memory of each reviewer only through `agent/copilot/memory.py`, the one place with `PAYROLLCHECK_COPILOT_MEMORY_ID` and the reviewers' namespaces, on the AgentCore store in `agent/agentcore_memory.py`. The app's operations the payroll agent calls on its route are named once, in `agent/app_operations.py`, and the context layer's tools once, in `agent/context_tools.py`. The Copilot reaches the backend only through `agent/copilot/app_api.py`, one function per operation, each sending the reviewer's sign-in with `connection.call_as` and never the agent's key. Everything else the agent sends the backend, its bookkeeping included, goes through `agent/api.py` with the key. The dashboard reaches the backend only through `dashboard/src/api.ts`, on `dashboard/src/connection.ts`, the one place that sends a request and reads its answer or refusal, which nothing else uses, and Supabase Auth only through `dashboard/src/auth.ts`. Each API module has one function per backend operation, named after it. The agent reaches AgentCore Identity only through `agent/identity.py`, the one place with `AGENTCORE_CREDENTIAL_` and `requires_api_key`. The backend reaches the agent only through `backend/agent_service.py` and the Copilot only through `backend/copilot_service.py`, one function per operation, each sending one payload on one of two routes chosen per call: the AgentCore app's `/invocations` on the laptop, at `PAYROLLCHECK_AGENT` with the key or at `PAYROLLCHECK_COPILOT` with none, or its runtime through boto3's `invoke_agent_runtime` when `PAYROLLCHECK_AGENT_RUNTIME` or `PAYROLLCHECK_COPILOT_RUNTIME` names one; each service's settings are written in its module alone, and `/invocations` and the `bedrock-agentcore` client in `backend/runtime_calls.py`, which both use, alone. Committing what the app did for some work, asking for it to be taken and undoing it when it wasn't is `backend/asking.py`'s. What the app knows of the agent's work, such as how long it may go quiet, is `backend/agent_work.py`'s, and what it keeps of the Copilot's conversations `backend/conversations.py`'s. Scope is defined in `backend/scope.py` alone, and every route and query that reaches a case, a project or a subcontractor for a person takes it from there. Overrides are `backend/overrides.py`'s, notices `backend/notices.py`'s, and the outbox `backend/outbox.py`'s, whose `send_notice` is the one way a notice is sent and `deliver` the one place it leaves the app. Holding a case for a reviewer's work is `backend/reviewing.py`'s. The business date is `backend/business_date.py`'s, and every period is resolved by `backend/periods.py` with `data/payroll_world/periods.py`. The Copilot reads cases only through its own routes in `backend/copilot_reads.py`, and a flagged case's text is withheld in `backend/withheld.py` alone. A notice the Copilot drafts is worded by `backend/notice_drafts.py`, from the rule catalogue's words. The backend reaches the judge only through `backend/judge.py`. Only `backend/grading.py` grades notices with it. What the improver reads is `backend/improver_view.py`'s, the check tools' tunable parameters and their bounds `backend/parameters.py`'s, the keep-or-roll-back rule `backend/verdict.py`'s, and the success criteria and their thresholds `backend/success_criteria.py`'s. The base URL and each path are written once, there, and no other module builds a URL or sends a request.
8. Each module has one job, and its name says what it is. A module uses another through what that module is for, and never borrows its helpers. A helper two modules need goes in a module of its own. No circular imports. Tests follow the same rule: shared test helpers live in their own module, never in another test file.
9. Write a literal once. A URL, a path, a status or a message used in more than one place is named once, in the module that owns it.
10. Use the framework's own way before writing your own: FastAPI dependencies and models, `BedrockAgentCoreApp`'s entrypoint, async tasks and `/ping` for the agent's operations, a Pydantic discriminated union for their payloads, LangChain's `context_schema` with `ToolRuntime` for what a tool needs to know, LangGraph's `StateGraph`, `ToolNode`, conditional edges, `RetryPolicy` and checkpointer for the payroll agent and the Copilot, LangGraph's `Send`, `max_concurrency` and `RetryPolicy` for the dispatcher, LangChain's `create_agent` with `HumanInTheLoopMiddleware`, `ModelCallLimitMiddleware` and middleware hooks for the improver, a LangGraph store passed at compile for the Copilot's memory, tool artifacts for the steps a tool records, `MultiServerMCPClient` for MCP tools, FastMCP for the context layer's server, SQLAlchemy Core for the database, with a conditional update that checks its row count for a move only one caller may make, React hooks and shared components. Check the documentation for the installed version.
11. A function does one job. Split one that mixes levels of detail, such as setting up a run, driving the agent and recording the result.
12. When you extend code, bring it up to these standards first. Never copy a pattern they rule out.

## The agent

13. The agent's parts are kept apart. `connection.py`, `api.py` and `improver_api.py` are the backend's API, with the app's words for its records in `app_terms.py` and how a model is told a refusal in `refusals.py`, which use nothing else in the agent, and `routes.py`, `gateway.py`, `direct.py` and `mcp_tools.py` are the payroll agent's two routes to its tools, which use nothing else in the agent but `direct.py`'s use of `api.py`. The check tools in `agent/checks/` are pure functions of `CheckInputs`, the plain data in `checks/inputs.py`, and the version's parameters, and they compute every rate and shortfall with `context/wage_rules.py`; they import nothing else of the agent or the context layer, and the rule codes on the agent's side are theirs, in `checks/findings.py`. `check_inputs.py` reads `CheckInputs` from the app's records and the context layer's lookups on the payroll agent's route, each lookup asked once. `tools.py` holds the model's tools, the app's reads and its exception report with the context layer's lookups from `context_tools.py`, which both agents have, and the context and state the tools read; they reach the app only through the payroll agent's route, filling in the case, its project and its subcontractor from the context rather than taking them from the model. `harness.py` builds and runs the payroll agent, on the route `tool_route.py` chooses and the checkpoints `checkpoints.py` keeps: the screening, then the check node, which runs the eight checks in order and records each one's findings, then the model and its tools, with no pause and no memory, and the payroll graph's nodes do what middleware would. `screening.py` is the screening of every text cell of a payroll. `dispatcher.py` works a dispatch or an evaluation with no model, and reaches the payroll agent only through the harness's one function, `work_in_run`. `improver.py` is the improver, with its tools, its middleware and the context they read; it never imports the harness, the dispatcher or the routes, and works a round's evaluations through a function the entry point hands it. `entrypoint.py` is the agent's AgentCore app: it gets ready on its first request, checks the key off Runtime, reads each operation's payload, and hands the work to `work.py` on a thread of its own, registered as an async task, with the plumbing both AgentCore apps share in `agentcore_app.py`. `work.py` works a run through the dispatcher and a round through the improver, each telling the app every minute while it goes on, and the app why it stopped when it fails. `identity.py` fetches the agent's credentials from AgentCore Identity on Runtime, and `heartbeat.py` tells the app every minute that a piece of work is still going; each uses nothing else in the agent. Rules about cases are enforced by the backend and the Gateway's Policy, whatever the agent does: no exception carries a shortfall no check tool found, and every case the agent works ends Awaiting review.

14. Instructions give an agent its goal, what it has to work from and what done looks like. They don't script its steps: it plans those itself. Anything that must always happen, or happen in a fixed order, is done by the code.

## The Copilot

15. The Copilot is a part of its own, in `agent/copilot/`, with the same rules as the payroll agent. Of the rest of the agent it uses only `connection.py`, through `app_api.py`, its API on the app and the only one of its modules that uses it, and the shared modules, `checkpoints.py`, `tool_route.py`, `context_tools.py`, `agentcore_memory.py`, `agentcore_app.py` and `identity.py`, with `app_terms.py`, the app's words for its records that both agents read, `refusals.py`, `routes.py`, `openrouter.py`, `json_text.py` and `console.py`; nothing in the payroll agent imports it. `tools.py` holds its tools and the context they read, with what its filtered reads take in `filters.py` and its instructions in `instructions.py` and `instructions.md`: the reviewer's sign-in, the reviewer as the app gave them, the conversation, the turn and the route, which reach the graph and the tools in LangGraph's context and are never saved. `cards.py` records each step as a card with the app. `graph.py` is its hand-written LangGraph graph: the model and a `ToolNode`. `turns.py` works a turn and tells the app how it ended. `waiting.py` and `needs_a_reviewer.py` wait for the agent's work and work out what needs a reviewer, in code. `memory.py` is its memory of each reviewer. `entrypoint.py` is its AgentCore app: it gets ready on its first request, checks the reviewer's sign-in and the turn with the app before it answers, keeps one turn at a time for each conversation in its process, and hands the turn to `turns.py` on a thread of its own, registered as an async task. It asks for no key, since everything it does carries the reviewer's sign-in. It never signs off, sends back or overrides a case. Its tools are thin: each calls one route and returns what it says, and the scope, the periods, the arithmetic, the formatting of money and the withholding are the backend's. Rules about cases are enforced by the backend, whatever the Copilot does.
16. What must always happen is code: the check of the sign-in, the memory's lookup and save, and the waits. The Copilot's instructions give it its goal, who it works for, what it can see and do, and how to answer.
17. The sidebar is the dashboard's part of the Copilot: `components/Copilot.tsx` and its parts, with the conversation's shape and how it's read in `conversation.ts`, and what the sidebar shows and remembers in `copilot.ts`. It reads and sends through `api.ts`, with `useLoad` and `useAction`, like every page, and shows only what the app's records say.
